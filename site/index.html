What it actually does

The boring, true part

Everything on this page is a joke except this section, the commands, the install steps and the FAQ answers marked real.

A lead plans the work

You give it a goal. It splits the goal into threads in PLAN.md, each owning a disjoint set of files, then dispatches by priority.

Translation: a to-do list with opinions.

Workers run in the background

Up to max_workers background Claude agents build threads side by side. As one finishes, the next ready thread starts. Each is told only: follow WORKER.md, your thread is in PLAN.md.

Translation: five terminals, zero of them yours.

File locks, not worktrees

A thread declares the files it owns:. Touching anything else takes a lock first: mkdir .hyper/locks/<path> is atomic and fails if someone has it. No daemon.

Translation: a polite sign on the bathroom door.

A shared log

Workers append to .hyper/log.md, ask for contract changes with NEED, and release files when an urgent thread shows up.

Translation: a group chat where everyone has read the instructions.

Markdown-only state

All state is plain files in your repo (PLAN.md and .hyper/). Edit PLAN.md by hand whenever you like; the lead and workers re-read it.

Translation: the database is a text file. Yes, really.

No dependencies

It needs the claude CLI and bash. A 7-line shell script installs it, and ./uninstall.sh removes everything it installed.

Translation: nothing to upgrade at 2am.

Commands

Seven commands. You will use two.

CommandWhat it really doesVibe
/hyper:initWrites or refreshes CLAUDE.md, creates .hyper/, asks for config (or --defaults), then offers to run /hyper:plan.Sets the table.
/hyper:plan <N> "<goal>"Splits the goal into threads in PLAN.md and runs up to N workers until all are done. No args with an existing plan resumes.The big red button.
/hyper:add [-p N] "<task>"Adds one thread with priority 1-10. Starts a worker now if deps are done and a slot is free (or priority is 9+). Priority 10 logs [lead] URGENT."Also, one more thing."
/hyper:do "<task>"One fire-and-forget worker, right now, outside PLAN.md. With no args it drives all ready threads.Rename foo to bar. Go.
/hyper:statusDone/total, each thread's status, held locks and the last 10 log lines. Changes nothing unless asked.Refresh, but legal.
/hyper:config [key=value]Sets limits, rigor, model, dev mode and the Code Mode record. Running work picks it up.Knobs.
/hyper:clean [--keep-plan]Deletes .hyper/ and, unless --keep-plan, PLAN.md, after listing everything and asking.Fresh start energy.

Pricing

Pick a plan. They all cost $0.

Hyperdo is MIT-licensed and free. The three plans are the three real dev_mode settings, which only differ in how workers use git.

Solo

$0 / forever
  • Shared tree, small commits on main
  • git pull --rebase and git push often
  • No PRs

For people who push to main and sleep fine.

Most popular*

Pro

$0 / forever
  • Branch per thread, conventional commits
  • Affected tests, PR via gh
  • The lead merges after checks pass; never pushes to main

*Popularity not measured.

Prod

$0 / forever
  • Everything in Pro, plus rigor=slow
  • A worktree per thread, fresh-context review, CI green
  • No force-push, a CHANGELOG entry, and your approval before merge or deploy

For people who read the runbook.

Your Claude usage is billed by Claude as usual. Hyperdo adds no network calls of its own.

FAQ

Questions, some answered

realWhy do the commands say hyper?

The plugin is named hyper; the repo and marketplace are hyperdo. Commands are namespaced by plugin.

realDo I need git worktrees?

No. Isolation comes from disjoint file ownership and mkdir locks in one working tree. (prod mode does use a worktree per thread.)

realA worker died and its thread is stuck on doing.

Run /hyper:status and tell it the worker is gone. It resets the thread to todo and removes the locks.

realDoes it test my code?

As much as rigor says. By default each thread runs only its own check:, and the lead runs one cheap whole-project check at the end. Passing checks print nothing; on failure you get the exit code, the first few error lines and a log path.

realWhat does it send where?

Hyperdo adds no network calls of its own. The agents talk to Claude as usual, and in solo mode workers git push to your origin. The installer only runs claude plugin commands against this directory.

realHow do I remove it?

./uninstall.sh removes ~/.claude/hyperdo, the plugin and the marketplace. Per-project state stays; run /hyper:clean in each project for that.

jokeWill it replace me?

It cannot replace you. Somebody has to press Enter and then say "interesting" at the terminal.

jokeIs this a real product?

The tool is real and the install steps below work. The charts, the testimonials and the logos are not. We tried to be clear about that.

jokeWhy is the mascot sweating?

It is juggling five checkboxes and four are ticked. That is the best possible outcome and it is still stressful.

Install

Get it done. Or at least get it started.

Needs the claude CLI and bash.

git clone https://github.com/grplyler/hyperdo.git
cd hyperdo && ./install.sh

Restart Claude Code, then run /hyper:init and /hyper:plan in any project.
